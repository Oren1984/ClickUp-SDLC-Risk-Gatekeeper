The Problem

Tasks enter development before they're ready

Small teams, solo builders, and technical project managers often move tasks into sprint without all the information needed to develop them safely. The cost of catching gaps in planning is near zero. The cost of catching them in production is high.

📋 Missing Acceptance Criteria

No clear definition of what "done" means. Developers must guess.

🧪 No QA Plan

Tasks enter development with no test cases, edge cases, or QA expectations defined.

🔒 Security Without Validation

Auth, payment, and encryption tasks proceed without security notes or threat model.

🤖 AI Features Without Guardrails

LLM features go into development without fallback behavior, safety controls, or content filters.

🏗️ Architecture Changes Unreviewed

Database migrations, API redesigns, and infrastructure changes skip technical review.

⚖️ Compliance Without Evidence

GDPR, PCI, and HIPAA tasks have no documented evidence, DPA reference, or sign-off.

✅ Definition of Done Incomplete

Tasks marked ready without confirming code review, staging deploy, or DoD checklist.

🚫 Blocked but Active

Tasks with unresolved dependencies are assigned to developers, causing blocked sprints.

The Solution

An automated SDLC gate before development starts

The ClickUp SDLC Risk Gatekeeper reviews each task against 10 deterministic rules and returns a structured assessment. Every task gets a risk score, a gate decision, and practical recommendations before a developer touches it.

0–100
Risk Score

Weighted score based on rules triggered. Higher = more gaps.

Low
Risk Level

Low · Medium · High · Critical — derived from score range.

Findings
Gap List

Each triggered rule explains exactly what is missing and why it matters.

Recs
Recommendations

Practical next actions for the PM, QA, security, or architecture team.

Gate
Gate Decision

One of six outcomes: Approved, Clarification, QA, Security, Arch, or Blocked.

Gate Decision Meaning
✅ Approved for Development Task passes all quality gates — ready to enter sprint
💬 Needs Clarification Minor gaps must be resolved before development starts
🧪 Requires QA Review QA lead must review and approve before dev starts
🔒 Requires Security Review Security, compliance, or AI-safety team must sign off
🏗️ Requires Architecture Review Tech lead or architect must review system impact
🚫 Blocked Cannot proceed — blocking dependency or critical gap unresolved

Architecture

Adapter-based, mock-first, future-ready

The system is intentionally flat and readable. The active demo uses local ClickUp-style JSON. The adapter layer is designed to be replaced with a real project-management API when needed. 

── Demo Data Layer ─────────────────────────────────────────────────────

data/clickup_demo/tasks.json              ← 20 mock ClickUp-style tasks
data/clickup_demo/policies.json           ← risk thresholds + gate definitions
data/clickup_demo/definition_of_done.json ← DoD checklist
             │
             ▼
── Integration Adapter ─────────────────────────────────────────────────

src/core/clickup_adapter.py               ← active mock adapter
                                             TODO: replace with real API
             │
             ▼
── Risk Engine ─────────────────────────────────────────────────────────

src/core/risk_rules.py                    ← 10 SDLC risk rules (deterministic)
src/core/risk_reviewer.py                 ← scoring + gate decision logic
src/core/compliance_checks.py             ← GDPR / PCI-DSS / HIPAA / SOX
             │
             ▼
── Report Layer ────────────────────────────────────────────────────────

src/core/report_generator.py              ← per-task + project summary
             │
             ▼
── Dashboard ───────────────────────────────────────────────────────────

app/streamlit_app.py                      ← Streamlit SDLC risk dashboard

All components are pure Python with no external services required. The risk engine is deterministic and runs offline. No API keys, no cloud, no database.

AI Governance

Human-in-the-Loop by design

The gatekeeper is a decision-support tool — not an autonomous decision-maker. AI recommendations are advisory. Final gate decisions are always owned by a human reviewer.

Advisory
AI Role

AI generates risk scores, findings, and recommendations. Humans make all final calls.

Explainable
Transparency

Every finding states exactly which rule triggered, what is missing, and why it matters.

Flags Gaps
Uncertainty

Missing data is always reported as a risk signal — the system never assumes compliance.

No Auto-Block
Human Control

No task is automatically blocked or approved. Human review always precedes any gate outcome.

Role Responsibility in HITL Workflow
AI SystemGenerates risk assessment, findings, and recommended actions
PMReviews findings, drives clarification, owns sprint readiness decision
QA LeadValidates QA readiness, reviews QA-flagged tasks, confirms test plan
Tech Lead / ArchitectReviews architecture-flagged tasks, confirms design decisions
Security / ComplianceSigns off on security, AI safety, and compliance-flagged tasks
Task OwnerUpdates task fields to resolve findings after review

Future Integration

ClickUp API ready — when you need it

The ClickUp API integration is intentionally not active in this version. The project is demo-first. The integration boundary is designed, documented, and future-ready — activation requires only implementing the prepared adapter. 

── Integration Layer (future-ready skeleton) ────────────────────────

src/integrations/base.py              ← TaskClient protocol (interface)
src/integrations/mock_client.py       ← active mock (reads local JSON)
src/integrations/clickup_api_client.py ← placeholder (NotImplementedError)
             │
             ▼
── When activated, will fetch from ClickUp v2 API ──────────────────

GET /api/v2/list/{list_id}/task       ← pull tasks from workspace
POST /api/v2/task/{task_id}/comment   ← post review findings (human-approved)
POST /api/v2/task/{task_id}/tag/risk-X ← apply risk label
What stays the same What changes when activated
Risk engine, rules, scoring, gate logic Data source: JSON file → live ClickUp API
Streamlit dashboard and UI Adapter: MockTaskClient → ClickUpApiClient
Compliance checks and report generator Authentication: add CLICKUP_API_TOKEN env var
All tests except integration tests Optional write-back: comment, label, status updates

See docs/FUTURE_CLICKUP_API_READINESS.md for the full integration roadmap. No tokens are committed. No credentials are required to run the demo.
